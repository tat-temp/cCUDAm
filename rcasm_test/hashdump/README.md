# hashdump — verifying a lifted `getHash160_w2` inside a hand-written RCAsm kernel

Branch `f2m`, full-pipeline hash lift. This harness retires the core risk of the effort:
**can the compiler's `getHash160_w2` SASS be lifted verbatim into a hand-written `asm/tk`
kernel and still compute the right answer?** Both stages pass on an RTX 5090 (sm_120).

The hash is SHA-256 + trimmed RIPEMD-160 returning word 2 of the HASH160 of a compressed
pubkey (`prefix(02/03) || X`). It is 32-bit-only, has no scoreboard barriers, no local
memory, a single `RET`, and ~30 registers — so it lifts nearly verbatim (drop the `RET`,
`call_func` appends the `BRXU` return).

## Pieces

| file | role |
|---|---|
| `hashcheck.cpp` | HOST reference: compiles `GpuHash.cu` with device→host shims, runs a KAT (`hash160(02‖Gx)`), and dumps `hashgolden.bin` |
| `hashgolden.bin` | golden fixture: `u32 N`, `X[N*4] u64` (LSB-first), `pref[N] u8`, `hw2[N] u32` |
| `hd_runner.cpp` | driver-API runner; modes `stub` and `golden`; reuses the 7-param `TestKernel` template ABI (Px=X in, Py=prefix u64, Scal=out u32, threadsTotal=N) |
| `shim/` | empty `cuda_runtime.h` / `device_launch_parameters.h` so `GpuHash.cu` compiles on the host |
| `../../asm/tk/hd_test_main.asm` + `hd_test_inc.asm` | **Stage 1**: proves the `call_func`/`BRXU` call mechanism (stub `Rout = Rin + 0x1234`) |
| `../../asm/tk/hd_hash_main.asm` + `hd_hash_inc.asm` | **Stage 2**: loads `X[gid]`+prefix, calls the LIFTED `getHash160_w2`, stores `hw2` |
| `../../asm/tk/hd_{test,hash}.cubin` | committed build outputs (the run-host cannot build RCAsm cubins — same reason `asm/tk/*.cubin` are tracked) |

`hd_hash_inc.asm` is the lifted hash (2008 instrs). It is generated by disassembling a fresh
compile of `GpuHash.cu`'s `getHash160_w2_from_limbs`, stripping the `/*addr*/` prefixes and
trailing `;`, and dropping the terminal `RET.ABS.NODEC`. Inputs: `prefix=R4`,
`e0..e7 = R13,R12,R11,R10,R9,R8,R7,R6` (e0=hi32(x.v[3]) .. e7=lo32(x.v[0])); output `hw2=R4`;
only uniform reg `UR4`. The kernel keeps `uDesc`/`uCallH` off `UR4` so the body needs no
renumbering.

## Build & run

Golden (host, no GPU) — from repo root:

```
g++ -O2 -I rcasm_test/hashdump/shim -I . rcasm_test/hashdump/hashcheck.cpp -o hashcheck
./hashcheck            # KAT + writes rcasm_test/hashdump/hashgolden.bin
```

RCAsm cubins (WSL, CUDA 13.0, RCAsm checkout) — from `asm/tk`:

```
sed 's/\r$//' build.sh > _build_lf.sh
MAIN=$(pwd)/hd_hash_main.asm INC=$(pwd)/hd_hash_inc.asm OUTNAME=hd_hash.cubin bash _build_lf.sh
MAIN=$(pwd)/hd_test_main.asm INC=$(pwd)/hd_test_inc.asm OUTNAME=hd_test.cubin bash _build_lf.sh
rm -f _build_lf.sh
```

Verify on the GPU host:

```
g++ -O2 -w hd_runner.cpp -o hd_runner -I$CUDA/include -L$CUDA/lib64/stubs -lcuda
./hd_runner ../../asm/tk/hd_test.cubin stub                        # Stage 1
./hd_runner ../../asm/tk/hd_hash.cubin golden hashgolden.bin       # Stage 2
```

## Results (RTX 5090, sm_120, CUDA 13.3)

- **Stage 1** (call mechanism): `stub` 256/256 correct.
- **Stage 2** (lifted hash): `golden: N=8192 mismatches=0 PASS` — bit-exact.

The native `CALL.REL.NOINC` / `RET.REL.NODEC` call type (what `GpuCore.cu` uses) was tried
and **fails** under RCAsm injection: the forward `CALL` and label MOV resolve, but
`RET.REL.NODEC`'s base fixup is miscomputed and the kernel dies `ILLEGAL_INSTRUCTION` at
launch. RCAsm's `call_func`/`BRXU` (uniform-pair return, like `InvMod256`) is used instead —
proven, and costs zero R registers.
